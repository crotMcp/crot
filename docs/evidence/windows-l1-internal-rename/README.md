# Windows L1: переименование, точные снимки и штатный запуск AppContainer

**WP-23c не принят; PR27 Draft.** Исходный HEAD последней квалификации:
`a36a701b3b4d1b222f619a685880a5c9ab619625`. Последующая публикация этого каталога
и отчётов не меняет исходники. Полный отчёт и восемь критериев:
`docs/design/windows-l1-curator-appcontainer.md`.

## Что подтверждено на Windows Node20 и Node22

- `bd96740`/`a36a701`: запись существовавшего файла, переименование файла и его
  каталога туда/обратно — семь шагов с кодом 0; обычные файлы повторно открыты
  по проверенному исходному NTFS ID, а не старому pathname. Независимые исходные
  SD **13/13**, cleanup=true. Ошибка идентичности/чужих ACE означает отказ очистки.
- `5d4791d` и позднее: root/temp/cache/protected file/external hardlink удержаны
  эффективными no-DELETE-share guards; пять owner-rename проб получают Win32=32.
  Общие предки не переименовывались диагностикой. Они сохраняют тот же запрет
  DELETE sharing. Внешние hardlink readonly, внутренние RW; опасные открытия
  семи предков отклоняются. Все гонки и вложенные multi-link деревья не приняты.
- Настоящий CrotService: 5 чтений +5 записей +управляющий канал под AppContainer
  получают EPERM. Состояние неизменно, владелец аутентифицирован после проверки.
  Отдельно проверены owner setup и восстановление SD скрипта актёра.
- `394c1e8` и позднее: выбранный AppContainer-компонент NativeProcessLauncher,
  реальный byte stdio 1 МиБ stdin/stdout +256 КиБ stderr, Unicode argv и exit=23;
  отдельный canary и запись вне workspace отклоняются. Это не регистрация всего
  production CommandConfinement и не доказательство работы всех потомков.

## Что не прошло и почему это не скрыто

`0f9a998`: сначала прошли 13/13 ACL и существовавший файл, но не переименование
каталога. `9dd1107` конечным owner-контролем без изменения ACL показал ограничение
NTFS: открытый дочерний файл блокирует rename каталога даже при DELETE sharing;
после закрытия этого handle rename успешен. `bd96740` устранил этот дефект
для обычных существовавших single-link файлов; защищённые handles не ослаблены.

На `a36a701` оба Windows CI ещё неуспешны на обязательном detached-descendant
тесте. Родитель остаётся жив, трасса содержит parent-start/before-spawn, но
не after-spawn. `pipeCreationDiagnostics` выполняет ровно шесть попыток только
собственных свежих pipe instances, без retry и без изменения общих ACL:

| namespaceIndex | Пространство | Default DACL | Явный DACL только владельца/package SID |
| --- | --- | --- | --- |
| 0 | Обычный pipe namespace | Win32 5 | Win32 5 |
| 1 | Точный не-LOCAL prefix libuv | Win32 5 | Win32 5 |
| 2 | LOCAL | Создание/закрытие 0 | Создание/закрытие 0 |

Результаты одинаковы на Node20/22. Исследованный upstream libuv повторяет
ERROR_ACCESS_DENIED при создании своего не-LOCAL pipe как коллизию имени.
Это согласуется с синхронным зависанием spawn; стек потока не снимался.
Ни перевод гейта в пропуск, ни смена теста на вариант без захвата stdout,
ни выдача доступа к общему pipe namespace не применялись.

`9d43771` завершился без пакета событий. Сохранены annotations/checks и локальный
журнал; точная причина Windows без raw logs неизвестна (API журналов вернул 403).
Этот прогон не считается доказательством отказа доступа. Найденный по исходникам
LPWSTR ABI-дефект исправлен в `394c1e8` и проверен скомпилированной allocator/UTF16
фикстурой; последующие реальные Windows прогоны возвращают полные события.

`1f015ff` только по явному разрешению куратора сделал отвергнутый Low token spike
опциональным исследованием через CROT_WINDOWS_REJECTED_TOKEN_RESEARCH=1.
Его исходные assertions сохранены; AppContainer/WinPS/RPC/native-process и
настоящий CROT-6A остаются обязательными. Нестабильный старый native-process cmd
случай в `394c1e8` сохранён среди неуспехов; позднее он проходил, тест не ослаблен.

## Формат и проверка

Файлы `*.events.gzip.json` содержат полные пакеты событий. Дополнительный суффикс
`.gzip.json` у больших API-ответов, сводок или логов означает такое же сжатие без
потерь: originalFilename, gzipBase64, decodedBytes, decodedSha256. Декодировать
base64, распаковать gzip, проверить размер и SHA256 исходных байт. Сводки содержат
полные исходные SD; локальные журналы не обрезаны. Manifest фиксирует SHA256
каждого физического файла каталога, кроме самого manifest.

`tested-merge.json` связывает тестировавшийся merge с исходным HEAD и обоими
родителями, проверяя source parent index=1. `checks` содержит все задания CI,
`native-summary` — результаты обоих Node, `selectedLauncherEvents` — компонент
запуска и точную неуспешную трассу потомка. Отсутствие события не трактуется
как отказ доступа или успех. Токены/содержимое секретов не публикуются.

Локальный npm run check последнего исходного HEAD: код 0, Linux x64/Node24,
1767 Core +147 extension, 172 skipped. Это не Windows-доказательство. CI:
9 успешных/2 Windows неуспешных; выбранный SDK ACL/CRUD/CROT-6A гейт проходит,
но обязательный detached-потомок не проходит. Фактическая Windows-платформа —
повышенный Server2025 x64. Обычный пользователь, Windows11/Server2022, ARM64,
аварийная очистка, сеть on/off/localhost, Docker pipe и production backend
ещё не приняты. Исторические каталоги доказательств не изменялись.
