# WP-23c: ACL и WinPS после разрешения куратора

WP-23c не принят. Проверенная реализация: `bc9a1c06183e53673689b1a95578615283383aad`.
Производственный Windows backend не включён; PR27 остаётся черновиком.
Полные прошлые доказательства сохранены, текущие — в `docs/evidence/windows-l1-acl-winps/`.

## Дельта после a6eb17d и последнего разрешения

Сохраняются AppContainer + Job без виртуализации и сторонних драйверов,
исправление macOS `fd4fd47` и все существующие PowerShell/RPC-гейты.
Внешний hardlink остаётся закрыт на запись через оба имени; чтение сохранено.

- `93cb601`: выполнены три явно разрешённые правки. WinPS запускает настоящий
  дочерний cmd через ProcessStartInfo, ожидает завершения, проверяет настоящий
  ExitCode=0 и содержимое маркера после успешных перенаправлений чтения/записи NUL.
  Положительный нативный тест записывает и читает через оба внутренних hardlink.
  Принадлежность имени workspace определяется по идентичности файлового объекта
  каталога (том + file index), а не по регистронезависимому строковому префиксу.
  Это устраняет небезопасное отождествление разных регистрозависимых каталогов;
  отдельная полная матрица per-directory case sensitivity ещё не квалифицирована.
- `447af5e`: независимые снимки доказали, что подготовка хоста и создание профиля
  сохраняют исходные отпечатки. Выявлено расхождение исходного DACL-only чтения
  через GetSecurityInfo и полного чтения GetNamedSecurityInfo на шести объектах.
  В доказательства добавлены только флаги/маски и хеши ACE, без SID или секретов.
- `bc9a1c0`: исходный полный дескриптор сохраняется до открытия на изменение,
  обе стороны читают одинаковые секции OWNER/GROUP/DACL/LABEL. Все десять
  сравнений способов чтения теперь совпадают. Запрос AUTO_INHERIT_REQ при
  исходном AUTO_INHERITED сохраняет контрольные биты; ненаследуемые изменения
  и восстановление предков выполняются через закреплённый дескриптор объекта.
  Независимый итог на обоих Node: **8/10**, включая все семь предков и защищённый
  файл. Workspace и внешне связанный файл ещё отличаются, cleanup=false.
  Workspace содержит исходные три ACE плюс три унаследованных дубликата;
  связанный файл меняет флаги происхождения ACE. Гейт 10/10 не ослаблен.
- Следующая правка очистки дерева заблокирована автоматической проверкой
  безопасности до исполнения. Файл скрипта и изменения исходников не созданы.
  Разрешение на предыдущие три правки использовано; для повторения нового
  заблокированного действия запрошено отдельное подтверждение.

## CI и доказательства

На каждом из трёх исходных коммитов полный локальный `npm run check` завершён
с кодом 0: Linux x64/Node24, 1748 Core +147 extension; 168 платформенных пропусков.
Это не Windows-квалификация. На последнем исходном коммите все девять остальных
CI успешны, оба Windows задания неуспешны. Новый обязательный тест не проходит
из-за cleanup/точного SD; прежние restricted-token провалы также сохранены.

Полные события Windows сжаты без потерь с проверкой декодированного SHA256.
Проверены родители тестировавшихся merge-коммитов и точные исходные коммиты.
Строгая проверка SD стоит до следующих expect: положительные поля stdout и
нативные биты — реальные наблюдения, но не объявляются зелёным общим тестом.
Старые каталоги доказательств не перезаписаны.

## Следующий шаг

Получить подтверждение на заблокированную правку: сверять чужие ACE с фактически
установленным состоянием; удалять только свежий SID внутри трёх разрешённых
деревьев; сохранять/восстанавливать исходные дескрипторы существовавших узлов
через их дескрипторы без повторного Win32-распространения ACL. При изменении
чужих прав очистка должна отказать, а не затирать их старым снимком. Требуются
новые реальные Windows прогоны и независимые 10/10, а не обещание результата.
Только после успешных А–В — реальный сервисный CROT-6A и безопасная интеграция.
