# WP-23c: директива куратора без виртуализации

WP-23c не принят. Проверенная реализация: `e812f1d95c6d992b6a4f0ad8a1c4a731e8d3b36f`.
Производственный Windows backend не включён. Полный CROT-6A AppContainer
и пункт Г не объявляются выполненными до успешных А–В.

## Дельта после a6eb17d и последней директивы

- `98f7e0c`, `08bc430` фиксируют решение куратора: только AppContainer + Job,
  без Windows Sandbox/Hyper-V/HCS и стороннего драйвера. Разрешены readonly
  grants предков и запрет записи через оба имени внешне связанного файла.
- `b135766` вводит закреплённые DACL-снимки, перечисление ссылок и права
  чтения предков. Первый нативный прогон остановился ДО actor: MAXIMUM_ALLOWED
  запросил DELETE и получил sharing violation на корне. Этот запуск не принят
  за доказательство отказов песочницы. `4578702` подтвердил точную ошибку 32.
- `932be34` перешёл к минимальному открытию READ_CONTROL/WRITE_DAC и
  документированному непередающему SetFileSecurityW. Все семь предков читаются,
  WinPS выбирает workspace; 35 отдельных опасных открытий предков по-прежнему
  отклонены на каждом Node. Пустая строка/плохой startup не считаются denied.
- `fe6bd33` применяет одобренную альтернативу: защищённый DACL связанного
  файла без Modify песочницы, с конкретными write-deny и readonly-allow SID.
  На Node 20 и 22 оба имени возвращают ERROR_ACCESS_DENIED при GENERIC_WRITE,
  чтение сохранено, новая внешняя ссылка не создаётся; процесс и CRUD работают.
- `e812f1d` сохраняет все снимки предков ДО изменения любого из них, восстанавливает
  родителей раньше детей и исключает лишние переключения PROTECTED/UNPROTECTED.
  Оба обычных нативных потомка (с консолью и без неё) действительно завершены 0.
  Однако точное восстановление SD всё ещё не прошло: AUTO_INHERITED теряется
  у Users/корня, у ряда потомков изменяется происхождение ACE. Проверка сохранена.
- WinPS теперь начинает непосредственно в workspace. Его последняя проверка
  потомка остаётся неуспешной: LASTEXITCODE пуст, итоговый код WinPS=1. Это
  не объявляется успешным исправлением. Подготовлена более строгая проверка
  реального Process.ExitCode и файла-маркера; она заблокирована автоматической
  проверкой безопасности и НЕ применена. Повторение требует согласия пользователя.

## CI и доказательства

`npm run check` последнего исходного коммита: exit=0 на Linux x64, Node24;
1748 Core +147 extension, 168 платформенных пропусков. Это НЕ Windows-квалификация.
Реальные Windows Node20/22: оба задания неуспешны. Остальные девять заданий
на этом коммите успешны. Полные Windows события, локальные журналы и родители
тестировавшихся merge-коммитов: `docs/evidence/windows-l1-curator-appcontainer/`.
Старые 70 и 198 хешей доказательств не перезаписаны.

Отдельный ускоренный workflow не опубликован: GitHub вернул 403 на изменение
workflow. Штатный полный CI сохранён, ограничение доступа не обходилось.

## Следующий шаг

Получить разрешение на заблокированную правку: проверять фактический ExitCode
потомка WinPS плюс файл-маркер, добавить положительный тест внутренних hardlink
и уточнить сравнение регистрозависимых путей. Строгие ACL/hardlink/IPC гейты не
ослабляются. Параллельно остаётся найти и доказать точное восстановление SD,
включая AUTO_INHERITED и происхождение ACE, без распространения ACL по диску
или затирания чужих прав. Только после успешных А–В — реальный сервисный гейт
и безопасная интеграция CommandConfinement.
