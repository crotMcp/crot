# CROT design system

## Source of truth

The extension popup, onboarding and account pages use the
curator's **shadcn/ui Zinc Dark + Linear** design map. `src/ui/theme.ts` owns
static tokens and the capabilities catalog. `src/ui/i18n.ts` owns the offline
EN/RU/ES/DE/ZH dictionary and browser runtime. Extension CSS and localization are
generated by `scripts/build-extension-ui.mjs`; never edit generated copies.

Control Center has a curator-requested fixed light/blue desktop surface override in
`src/tray/control-center-welcome.ts`, layered over legacy tool styles; see [product architecture](CONTROL_CENTER_ARCHITECTURE.md). The compact Zinc geometry below applies to the unchanged portal/extension, not the new 44px Control Center controls.

System/Inter sans, no font CDN. Monospace only for commands, paths and diagnostics.

## Fixed component geometry

- Base: 13px / 1.5, weight 400; universal border-box and antialiasing.
- App H1: 16px / 600, tracking -0.01em. Card H2/H3: 14px / 600.
- Website hero H1 only: 32px / 700. No viewport-scaled giant headings.
- Labels/badges: 11px / 500, tracking 0.03em. Code: 12px, 6px 10px padding, radius 6px.
- Button: height 32px, horizontal padding 12px, 12px / 500, radius 6px.
- Primary CTA: height 36px, padding 16px, 13px / 500, radius 8px.
- Cards: padding 16px, radius 10px. Window margins 16px, grid gap 12px.
- Icons: bundled, decorative SVG strokes with accessible labels on icon-only actions.
- Below 700px: horizontal tab strip, single-column grids, no page-wide overflow.

The compact control heights are the curator's explicit desktop specification,
not a claim of 44px touch targets. Preserve keyboard navigation and visible focus.

## Stability and localization

Popup's first head stylesheet is `popup-geometry.css`: html and body are 380x520
before scripts/data. A static shell is present in HTML. Native connection changes
reserve the installation card's space rather than resizing the viewport.

Control Center caches rendered section inputs. Unchanged polling does not rebuild
modules, approvals, presets, clients or remote buttons. Navigation is never rebuilt.
User actions that materially change a section can update that section. Preserve
focus and scroll during unchanged background polling.

Language selection uses an explicit saved choice first, then navigator.language,
then English. RU/EN/ES/DE/ZH selectors appear in every surface. Translation uses
text nodes, not HTML. Paths, commands and approval values remain byte-visible as
presented; they must never be translated. Trusted dynamic messages preserve their
source text so changing language also works after an update.

## Trust and evidence

Free local use stays independent of cloud billing. Unknown cloud plan is not Pro
or Free. Keep complete approval subjects, visible hostile characters and warnings.
Raw IDs and provider details belong in collapsed Developer Diagnostics.

No renderer network or remote code in Control Center. Context isolation, Node
denial and strict CSP remain. Linux Electron `--no-sandbox` is an explicit
compatibility trade-off, not unchanged AD-19 sandbox guarantees; see AD-38.

Payment data belongs only in hosted Stripe Checkout. A redirect is not proof of
entitlement. Roadmap integrations remain explicitly unavailable. Never advertise
a download, L1 repair, live payment or native installer qualification not observed.

Run scoped tests and Chromium visual E2E, inspect screenshots, then full `npm run
check`, `npm run test:e2e:browser` and exact-head CI. Fixture UI tests do not prove
native OS integration, production deployment or installer readiness.
