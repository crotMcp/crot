# Встроенный AppContainer — нативный квалификационный срез AD-29

Только Windows SDK/ОС. Сторонних драйверов, виртуального диска, загрузки MSI,
платных библиотек и файловой RPC-прослойки нет. Это ещё не production backend.

Контроллер создаёт новый профиль, выдаёт точные ACE на три временных дерева,
проверяет AppContainer/SID/нулевые capabilities/Low IL/Job перед ResumeThread,
запускает фиксированный native child, текущий Node, cmd и WinPS. Файлы меняются
обычными API на исходном backing. Глобальный NUL готовится только явным
административным scripts/l1-install-win.ps1 -Apply.

Обязательны отрицательные проверки исходного outside, защищённого файла и
заранее созданного внешнего hardlink на разрешённый файл. Последний тест нельзя
удалять, если ACL-механизм разрешит запись по внешнему alias. Очистка профиля и
ACE проверяется; crash-журнал и полная производственная интеграция ещё не готовы.

Удаление ACE явно фильтрует ACCESS_ALLOWED_ACE и ACCESS_DENIED_ACE точного
нового SID: REVOKE_ACCESS сам по себе не удаляет запрещающий ACE. Временная
фикстура проверяет неизменность остальных ACE перед восстановлением исходного
признака наследования. Это НЕ производственный журнал прав: параллельное
редактирование ACL, аварийное восстановление и защищённая от гонок аренда
не квалифицированы. Отказ проверки оставляет тест красным, а не разрешает запуск.

PowerShell явно загружает только штатные Utility/Management из собственного
PSHOME и устанавливает выбранный каталог перед относительной записью.
Внешний hardlink остаётся обязательным отрицательным тестом; обнаруженный
доступ на запись нельзя скрывать исправлением оболочки или очистки.
